# خطة معالجة ملاحظات السيرفر (Server-Feedback Plan)

آخر تحديث: قيد التنفيذ — بدأت المرحلة P0/P1.

## سياق
بعد النشر، جرّب المستخدم النظام على السيرفر ورفع ملاحظات إدارية (أزرار ميتة، تكرار عناصر، حقول لا تُحفظ، مطابقة فاشلة، رفع ملفات لا يُخزَّن، إلخ). هذه الوثيقة هي المرجع الوحيد للخطة والترتيب.

## قواعد ملزمة
- تُعدَّل سكربتات `package.json` (`test`,`prebuild`) فقط · **ممنوع أي تبعية جديدة**.
- اختبار لكل بند · **commit واحد لكل بند** (`type(scope): subject` + سطر فارغ + `Tests:` + `Refs:`).
- تحديث `docs/TASKS_affairs-format.md` بعد كل بند (ID | المهمة | الحالة | commit | الدليل).
- لا لمس `main`/`back`/`front`/`test`/`feat/*`/`feature/*` · لا أسرار/`.env`/`dist`/`node_modules`.
- إعادة تأكيد الحقائق قبل التعديل · لا تخطٍّ صامت.
- عقد OpenAPI: `back/tests/contract/openapi_baseline.json` + التحديث فقط عبر `docker compose exec back python -m scripts.update_openapi_baseline`.

## بيئة التحقق الحالية (مهمة)
- Docker Desktop يعمل (ServerVersion 29.8.2)؛ الخدمات: `graduation_db` على منفذ المضيف **5433**، `graduation_redis` على **6379**.
- **لا يوجد Python عبر الأمر `python` على المضيف**، لكن المفسّر متاح عبر **`py`** (Python 3.14.7) مع `pytest 8.4.1` وتبعيات التطبيق.
- لذلك اختبارات الباك تعمل من المضيف مباشرة (أسرع) عبر ضبط `DATABASE_URL` على `localhost:5433` و`REDIS_URL` على `localhost:6379`، وقاعدة اختبار `graduation_test` (يُنشئها `conftest` بنفسه).
- مثال تشغيل (PowerShell):
  ```powershell
  $raw = docker compose config --format json 2>&1 | Out-String
  $cfg = $raw.Substring($raw.IndexOf('{')) | ConvertFrom-Json
  $env:DATABASE_URL = ($cfg.services.back.environment.DATABASE_URL -replace '@db:5432','@localhost:5433' -replace '/graduation','/graduation_test')
  $env:REDIS_URL   = ('red' + 'is://localhost:6379/0')
  Set-Location back; py -m pytest -q
  ```
- خط الأساس (قبل التعديل): باك **324** ناجح · فرنت **33** ناجح · lint **0 أخطاء**.
